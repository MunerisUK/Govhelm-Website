Platform

Architecture

One idea carries the whole design: the platform code is identical for every government, and each jurisdiction is a profile. Everything below is what it takes to make that true and keep it true.

Read the architecture packAPI reference

Common Core and Jurisdiction Profile

The platform is split along one seam. On one side, the Common Core: the capability catalogue, the citizen record, the policy decision point, the event bus, the identity resolver, the persistence seam and the renderer. On the other, the Jurisdiction Profile: everything true of one government and not of another.

The profile carries the constitutional facts (head of state, legislature, legal system), the departments and who owns which data domain, the identity schemes the jurisdiction accepts, the fiscal design, the data-protection regime and regulator, the languages and currency, the branding, the capability toggles, the data-sharing agreements and the residency rules.

Profiles are validated at load against a list of required variation points. A profile missing one does not start with a default quietly filled in — it fails, and says which field is missing. A silent default in a government platform is a governance incident waiting to happen.

The single citizen record

A thin master plus pointers. The master holds minimal identity attributes and lifecycle; everything else stays in the system that owns it and is reached by reference. A cross-domain consumer never receives the underlying value — it receives a claim the owning domain derived, such as whether a figure sits below a threshold.

The claim is the mechanism, not a courtesy. Because raw income appears in no agreement, it is denied to every consumer, for every purpose, including ones written next year by somebody who never read this page.

The policy decision point

Every cross-domain access is evaluated against the tenant’s active agreement register: the consumer, the domain, the stated purpose and the exact fields requested must all match an agreement, or the read does not happen. Decisions are scoped per tenant, so an agreement can never authorise an access in a different government.

Both outcomes are written to an immutable audit log that the citizen can read. Logging the denials matters as much as logging the permissions: a refused access is exactly the event an oversight body wants to see, and it is the one most systems throw away.

The event backbone

Capabilities react to each other without knowing about each other. An authoritative write publishes a fact carrying a reference; subscribers registered in the wiring module read the one record and act. Handlers are jurisdiction-agnostic and the tenant is passed at publish time, so one registration set serves every government and a handler only ever touches the tenant it was handed.

Two producers run today: a death registration and an income update. Both fan out by reference, and both fan-outs are policy-checked and audited on arrival, exactly like any other read.

The repository seam

Domain logic does not know where it is stored. The same code runs over an in-memory store for demonstrations and evaluation, or over Postgres in a real deployment, with a migration job that runs before the application starts. One database per government — not one database with a tenant column.

Server-side rendering

Each government’s portal is rendered on the server from its own profile: its logo, its languages, its currency, its enabled services. There is no client framework, which keeps the accessibility surface small, keeps the service working without JavaScript, and keeps the thing a citizen downloads to use a public service proportionate.

The decision record

Fourteen architecture decision records sit in the codebase and are served live by the admin architecture view, so the reasoning behind the platform is available from the running system rather than from a document that may have drifted.

The invariant

No jurisdiction name, no jurisdiction branch

The Common Core layer contains no jurisdiction name and no conditional on a tenant id. It is checked mechanically on every commit, because an invariant that depends on reviewers noticing is not an invariant.

When a government needs something the profile cannot express, the schema gains a variation point — available to every tenant — rather than the code gaining a branch. That is the discipline that makes one image serve eight very different constitutions, and the reason a security fix lands everywhere at once.

What the tests actually assert

That every committed profile loads and validates; that a jurisdiction with no personal income tax disables it by toggle rather than by fork; that a eurozone republic differs from a sterling monarchy only in profile values; and that every tenant forbids cross-tenant access.
