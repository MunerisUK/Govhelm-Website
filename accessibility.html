Platform

Accessibility

A public service everyone is obliged to use has to work for everyone who has to use it. WCAG 2.2 AA is the target for the platform and for this site, and the pages below say what has been tested and what has not.

The commitment

Every citizen-facing surface targets WCAG 2.2 AA. Accessibility is treated as a functional requirement of a government service rather than an audit to be survived, because a service somebody cannot use is a service they will have to queue for instead.

How the architecture helps

Pages are rendered on the server with no client framework. That is an architectural decision with an accessibility dividend: the markup a browser receives is the markup, the service works with JavaScript disabled or failed, and the surface that can go wrong for assistive technology is small enough to audit.

It also keeps the service usable on an old device over a poor connection, which for a citizen-facing government service is not an edge case.

This website

The site you are reading is built to the standard it describes. Text meets AA contrast in both light and dark themes, every link and control has an accessible name, the first tab stop is a skip link, the navigation menus are click-operated with expanded state and Escape support, and there is no horizontal scroll at narrow widths — tables and diagrams scroll inside their own containers instead of stretching the page.

The theme follows the operating system by default and remembers an explicit choice. The logo is artwork with a text alternative supplied separately, so the link keeps its name whichever version is showing.

What has been tested

Contrast ratios across both themes are computed rather than estimated. Keyboard operation, focus order and visible focus have been walked through on every page and every interactive control. Markup is semantic and validates, and every page works with styles and scripts disabled.

What has not

No independent accessibility audit of the platform or of this site has been carried out yet. No formal screen-reader testing matrix has been completed across assistive technologies. Both are scheduled ahead of the first production deployment, and the results — including the failures — will be published here, because an accessibility claim nobody can check is not worth making.

Telling us something is wrong

If any part of this site or the platform is difficult or impossible to use, we want the report more than we want the compliment. The route in is on the contact page, and accessibility defects are treated as defects rather than as enhancement requests.

Works without JavaScript

The script adds a theme toggle and menu behaviour. Every link and every service route is present in the markup regardless.

AA contrast in both themes

Every colour pairing is computed. Where a brand colour would fail against a surface, a different token is used rather than the ratio being rounded up.

Semantic structure

One main landmark, a logical heading order, labelled regions, and tables with proper header scope rather than layout dressed up as data.
