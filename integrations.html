Platform

The governed seam to everything else you run

GovHelm does not implement finance, payroll, HR or clinical care. It brokers them. Four reference connectors cross one seam with one set of guarantees, and a fifth system of record is defined against the same contract.

  • Instructions out, receipted
  • Every field policy-gated and audited

The seam

One contract, four targets

A connector is selected and configured entirely by tenant profile. Only the target and the field projection differ between them — which is why the fifth connector is a connector rather than a project.

Inbound summary + single sign-on · Built

CommVita

Health and care is not implemented natively. A tenant that runs the capability configures a CommVita connector in its profile and the platform hands off, or pulls a minimal care summary, across the seam.

Outbound data products · Built

Microsoft Fabric / OneLake

Publishes governed, minimised data products into the tenant’s own analytics estate. A data product is not a raw dump: every field is gated by the policy engine under a declared agreement and written to the audit log, so with no agreement nothing is exported at all.

Claims in, instructions out · Built

Finance / ERP

Reads minimised claims about a citizen’s finance account — below the means threshold, tax compliant — never the raw figures, and accepts outbound payment or posting instructions for the finance system to action.

Claims in, leaver out · Built

HR / Payroll

Government is also a large employer. The connector returns employment claims — is a government employee, employment active — never salary or pay band, and forwards a leaver instruction when a death is registered.

The rule

An export is an access, and is governed like one

The usual failure mode of integration is that governance stops at the edge of the application. Inside, every read is checked; outside, a nightly pipeline copies a table into a lakehouse and nobody can say which fields left or under what basis.

Here an outbound data product is not a dump. Every field is gated by the policy engine under a declared data-sharing agreement and written to the audit log, exactly like an in-app cross-domain read. With no agreement naming the analytics consumer, nothing is exported at all — governance by default, including for analytics.

The practical effect is that what leaves a government for its own analytics estate is visible, reviewable configuration in a profile, rather than logic buried in a pipeline nobody has opened since it was written.

What crosses the seam

  • Derived claims: below a threshold, tax compliant, employment active
  • Outbound instructions: a payment posting, a leaver notice
  • Receipts, so the instruction can be reconciled at both ends

What never crosses it

  • Raw income, salary, pay band or bank details
  • Clinical records beyond an agreed minimal care summary
  • Any field not named in an active agreement
  • Anything at all, if no agreement authorises the consumer

Configuration

A connector has two modes, and both are honest

With an endpoint configured, a connector is live and the call goes to that endpoint in a configured deployment. With no endpoint, it runs in mock mode and returns a representative governed payload, so the seam is demonstrable end to end without a live counterparty system.

Mock mode is what makes an evaluation environment useful. You can drive the whole journey — a claim read, a policy decision, an audit entry, an outbound instruction and its receipt — before anyone has opened a firewall.

The reference build does not perform the live transport itself; that is a deployment concern, wired per tenant. The site says so here rather than letting a demonstration imply otherwise.

Partner integration

CivitaOS: finance, payroll and HR against the same contract

CivitaOS provides government finance, payroll and HR as an external system of record. A published integration definition sets out exactly what it must build and what it must honour, with a conformance checklist as the acceptance gate.

A contract, not a hand-wave

The connector contract, the per-domain claim catalogues, the data-sharing agreements, outbound instructions, configuration, eventing, security and residency, and branding — all specified before either side writes code.

Non-negotiable invariants

Minimisation across the seam is first on the list: claims, never raw figures. Salary, pay band and bank details stay inside CivitaOS. An integration that breaks an invariant is not accepted.

It composes with the event bus

A death registered in the citizen record forwards a leaver instruction to payroll by reference. The producer publishes a fact; the connector reacts. Neither knows about the other.

The source of truth is the code

The integration definition names the platform modules and type declarations as the contract of record, so a conformance question is settled by reading the interface rather than by re-reading the document.
